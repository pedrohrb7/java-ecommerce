# Project instructions for this repo

Before any design, plan, or code change in this project, read
[`docs/CONSTRAINTS.md`](docs/CONSTRAINTS.md) and follow it. It holds the project-wide rules
(tech stack, package structure, auth/security rules, API error contract, documentation
conventions) that apply across every feature - not just whichever one is currently being
worked on.

A new spec or plan under `docs/specs/`/`docs/plans/` should only document constraints
specific to that piece of work; anything already covered in `docs/CONSTRAINTS.md` doesn't
need to be repeated there.

See [`docs/PRD.md`](docs/PRD.md) for the product vision this project is building toward.
